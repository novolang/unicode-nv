# Changelog

All notable changes to unicode-nv are recorded here. The format is
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this
package follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
with the pre-1.0 rule that a breaking change bumps the MINOR number.

## 0.1.3 — 2026-09-25

The functions that append to a caller's buffer declare that buffer
`var`: `ucase.to_lower_into`, `ucase.to_upper_into`, `ucase.fold_into`,
`unorm.normalize_into` and `udata.pack_bytes`.  Each always wrote into
the buffer it was given.  The next Novo release accepts such a write
only through a parameter declared `var`, and it refuses a call that
passes a buffer held under `let`.  A caller that passes a `var` buffer,
a new list or a copy has nothing to change.  The answers are unchanged.

- Four private helpers that append to a list take it as `var` for the
  same reason.
- Two tests hold the buffer they append to in a `var`.

## 0.1.2 — 2026-09-25

Two test helpers changed so that the tests build with novo 0.10.0
without a warning.  Each helper wrote the last element into its list and
answered the writer's result.  Each now writes and then answers the list
by its own name.  The library code and its signatures are unchanged.

- One private helper in `unorm` now spells its parameter marker `var`,
  which is the spelling the novo 0.10.0 formatter prints for `mut`.  The
  two spellings mean the same thing.

## 0.1.1 — 2026-09-24

The package builds under the list rule of the next toolchain, where a
list is one list under every name that holds it and a write into it
goes through a `var` name.  No public signature changed, and nothing
changes under 0.9.2.

### Changed

- `to_lower_into`, `to_upper_into`, `fold_into`, `normalize_into` and
  `pack_bytes` append to the caller's buffer through one private
  helper.  Under the next toolchain the bytes land in the caller's own
  buffer, which is what these functions are for.  A program that passes
  a buffer and then reads the buffer as it was before the call copies it
  first, with `list.slice(buf, 0, list.len(buf))`.
- `pack_bytes` builds the pack in a list of its own and appends it once.
- The private steps of decomposition push through a helper that takes
  the list as a `mut` parameter, which is the spelling `novo fmt` gives
  the `var` marker.

## 0.1.0 — 2026-09-18

Character classes, case mapping, normalisation, grapheme and word
boundaries and display width, over tables generated from the Unicode
16.0.0 Character Database.

### Added

- The tables, 187,094 bytes of them, generated by
  `tools/gen_tables.py` into four modules under `src/`: width, the
  UAX #29 break classes and the lexer predicates compiled in (38,705
  bytes), and the general category, the case mappings and the
  decompositions behind a `UniData` (148,389 bytes). The database files
  are not committed; the generator is, so every byte can be reproduced
  from the version it names.
- The conformance suites. `tests/uax29_tests.nv` and
  `tests/uax15_tests.nv` read the annexes' own test files. Against
  Unicode 16.0.0 this release passes 1,093 of 1,093 grapheme cases,
  1,826 of 1,826 word cases and 19,965 of 19,965 normalisation cases,
  the last checking all twenty equalities the UAX #15 conformance
  clause implies. A committed sample of each file runs with no
  download; `NOVO_UCD` runs the files whole.
- `tests/udata_tests.nv`, which queries every table behind the
  handle through the compiled-in tables and through a packed blob and
  compares the answers, and walks every refusal `data_from_pack` makes.
- `tools/alloc_scan.sh`, which reads the emitted code for calls to the
  allocator. It finds 57 functions on the width, break and predicate
  path, and none of them allocates.

### Changed

- `udata.UniData` gains a field, `pack: [u8]`, with a default of `[]`.
  `data_from_pack` borrows the bytes it is given and every later lookup
  reads out of that slice, and a struct of three scalars has nowhere to
  keep them. The field is not a breaking change. The default means that
  a `UniData { version: …, table_bytes: …, complete: … }` literal still
  compiles, and no function's signature moved.
- `ugrapheme.UniBreakState` and `UniBreakStep` are `@value` structs.
  They are four integers and a flag, and a terminal builds one per
  codepoint. Neither has any way to be mutated, so copying rather than
  sharing them cannot change what any program means.
- `udata.data_compact`'s description was wrong and is corrected. It
  said the handle was roughly a third of the size. It is a coverage
  policy over the same compiled-in tables. It answers for the Basic
  Multilingual Plane, reports the share of the tables it reaches in
  `table_bytes`, and makes no program smaller. A packed blob holding
  only what a program needs is what makes a program smaller.
- `unorm.quick_check` settles a "maybe" where one more lookup can.
  UAX #15's table answers maybe for a mark that might compose with what
  precedes it. This checks whether it actually does and answers `QcNo`
  when it does. `QcYes` and `QcNo` are both certain, and `QcMaybe` still
  means the algorithm has to run.
- One case in `tests/uclass_tests.nv` was factually wrong. It named
  U+2126 OHM SIGN as `ID_Start` and not `XID_Start`. The UCD disagrees
  and always has. The NFKC of the ohm sign is U+03A9, which is a
  letter, so the ohm sign is `XID_Start`. The rule is real, and the case
  now uses U+037A GREEK YPOGEGRAMMENI, whose NFKC is a combining mark.

### Known

- The tables read correctly on a device under a toolchain newer than
  0.9.1. Under 0.9.1 the length of a text constant on the bare-metal
  runtime stops at the first zero byte, and every table here opens with
  the entry for U+0000, so three of the eight checks in
  `tests/embedded_probe.nv` answer wrongly and the probe prints
  `FAIL: unicode-embedded 5`. Nothing here encodes around that. An
  alphabet avoiding the zero byte would cost a quarter of the table
  size and would hide the fault from the next package to meet it.
- A `list.map` whose callable is a local holding a type-annotated
  lambda leaks one object per element, which is filed against the
  toolchain as
  `codegen-llvm/list-map-over-typed-local-lambda-leaks`. This package
  uses named top-level functions instead, which is the shape that both
  lowers correctly and survives the device build's strict typing.
- Line coverage over `src/` is 100%. That is 1,065 instrumented
  statements and 1,065 executed, measured with `novo test --cov` over
  the eight suites and merged by hand, with no region excluded.
- `unorm.compare` allocates on the path that normalises. When both
  strings are already in the form it compares them as they stand and
  allocates nothing, which is the path a cache key or a filename
  comparison takes. Otherwise it normalises one starter-run of each
  side at a time and stops at the first difference, so neither
  normalised string is ever built whole.
- `data_from_pack` reads only a pack this release's format version
  wrote. The packed form is a header, a version string, a directory of
  ten section lengths and the sections. A blob with any other format
  version is refused rather than indexed into.

## 0.0.1 — 2026-09-11

The declarations: every signature, every type and every effect row,
with no function bodies.

### Added

- `uwidth` — display width by UAX #11 plus the zero-width categories
  every terminal adds to it. `char_width` is the exact
  `fn(Int) -> Int` that textwrap-nv's published `WrapWidth` holds,
  which is why it takes no table argument and why the width tables are
  compiled in.
- `ugrapheme` — UAX #29 extended grapheme clusters and word
  boundaries, in two surfaces over one algorithm: a cursor for a caller
  holding the string, and `break_step` for a terminal receiving one
  codepoint at a time.
- `unorm` — NFC, NFD, NFKC, NFKD, with `quick_check` and `compare` as
  first-class answers so the common case — text that is already
  normalised — costs no allocation.
- `ucase` — full case mapping and folding, with the language as a
  parameter because Turkish "i" is a different letter, and with folding
  separated from lowercasing because they answer different questions.
- `uclass` — the thirty general categories behind a `UniData`, and the
  predicates a lexer's inner loop asks compiled in without one.
- `udata` — where the tables live. Some are always compiled in, some
  are compiled in and asked for by name, and some are parsed from bytes
  the host read.

### Known

- No dependencies, and the absence is the design. Every text package on
  the registry is built on this one, so a dependency here would be one
  they all inherit.
- `uwidth`, `ugrapheme` and `uclass` build for a device, and `unorm`
  and `ucase` do not. Their tables are 245 KB, which is most of an
  nRF52's flash. Firmware that needs them reaches them through
  `udata.data_from_pack`.
- `ucase.fold` takes no language, deliberately. A fold is a comparison
  key, and one that depended on the reader's locale would make two
  systems disagree about whether two strings match. The Turkic variant
  is reachable through `simple_fold`.

### Design notes

Public type names are unique across a whole assembly, dependencies
included, so the `Uni` prefix is the package's convention. `UniCursor`
avoids `std.cursor`'s `Cursor` and pager-nv's. `UniBreakState` and
`UniBreakStep` avoid sql-engine-nv's `State` and the widely wanted
`Step`. `UniCluster`, `UniCategory`, `UniForm`, `UniData`, `UniWord`
and `UniEastAsian` avoid names another text package will want.

The module names matter for the same reason, and more sharply. Two
dependencies may not both ship a module of the same name. textwrap-nv
already ships `widths.nv`, and tui-nv depends on both packages, so
`uwidth` rather than `width`. `unorm`, `ucase`, `uclass` and `udata`
follow the same rule.
